# 极限属性模块详细设计

## 直接结论

极限属性模块应作为独立计算域实现，不从现有角色页、修炼页、法宝页等前端页面抽组件。现有页面只适合复用数据表加载、数值格式化和最终展示规范，不能作为计算口径来源。

第一版目标是复刻游戏运行时的角色属性面板链路，并在同一套计算核心上提供三类结果：

1. 角色总属性还原：按游戏运行时顺序合并各模块属性，计算角色面板战力。
2. 模块阶段曲线：玩家可以单独查看任意模块在任意阶段的属性值和战力值。
3. 极限方案：按目标 `maxFightPower` 或单项属性，输出指定阶段范围内的最优候选。

当前权威入口是 `D:\zmws\GameAnalysis\data\index.js`：

```text
UserInfoManager.getUserInfo(record, heroId)
  -> UserInfoManager.calUserInfo(...)
  -> UserInfoManager.calFightPower(attrs)
```

角色属性战力公式已由运行时确认：

```text
fightPower = floor(sum(attr[field] * powerAttribute[1][field]))
```

`powerAttribute` 必须从 `dataApi/powerAttribute.*.json` 读取，第一版只使用运行时确认的 `id=1`。`id=2`、`id=3` 未确认用途前不能暴露为可选战力口径。

## 范围边界

### 第一版纳入角色属性面板链路

这些模块出现在 `UserInfoManager.calUserInfo` 中，属于角色面板属性和战力计算范围：

| 顺序 | 模块 | 运行时入口 | 第一版处理 |
|---:|---|---|---|
| 1 | 角色等级基础 | `calAttribute_lv` | 严格计算 |
| 2 | 修炼/心法 | `calAttribute_xf` | 严格计算 |
| 3 | 装备基础/词条/强化/宝石 | `calAttribute_equipment` | 分阶段接入，装备候选优化单独做 |
| 4 | 装备套装 | `calAttribute_suit` | 与装备候选绑定 |
| 5 | 时装/宝珠 | `calAttribute_fashion`、`calAttribute_fashion_baozhu` | 分阶段接入 |
| 6 | 内丹页属性 | `getAttriByNeiDan_attr`、`calAttribute_neidan` | 先还原存档态，极限生成需继续追丹气/丹元 |
| 7 | 称号 | `getAttriByTitles` | 先按指定称号集合计算，极限候选需带可获得性标记 |
| 8 | 法宝/器魂 | `getAttriByMaigc`、`calMagicWeaponSoul` | 严格计算已给定法宝态，极限生成需枚举成长/祝福/器魂 |
| 9 | 翅膀 | `getUserAllWingsAttrsAndPower`、`getWingAttr` | 严格计算 |
| 10 | 羽毛 | `getUserAllFeatherAttrsAndPower` | 先还原存档态，极限洗练需继续追生成链 |
| 11 | 仙魄/炼体 | `calAttribute_xianpo` | 严格计算 |
| 12 | 阵法 | `calAllMatrixFightPower`、`calMatrixFightPower` | 先还原存档态，极限洗练需继续追阵核生成链 |
| 13 | 雁行/星核 | `calAllYanXingProperty` | 严格计算 |
| 14 | 经脉 | `calAllMeridiansightPower`、`calMeridiansFightPower` | 经脉等级严格计算，丹药属性生成需继续追 |
| 15 | 装备熔炼 | `getEquipSmeltAttr` | 严格计算已给定熔炼态，品质槽极限需枚举 |
| 16 | 吐纳 | `calBreathingPower` | 当前缺 `breathing`、`breathingAcupoint` 表，完整总属性阻塞 |

### 第一版不并入角色属性面板总值

这些系统在当前已核对的 `calUserInfo` 角色面板链路中没有出现，不能混入本模块的角色极限属性结论：

| 系统 | 处理 |
|---|---|
| 宠物 | 另起宠物/队伍战力链路，不并入角色属性面板极限 |
| 坐骑 | 另起坐骑/队伍战力链路，不并入角色属性面板极限 |
| 神器 | 当前更像战斗技能与独立装备表现，未确认进入角色属性面板属性汇总；先列为扩展链路 |
| 神魔/召神 | 使用 `callGodAttribute`、`callGodRatio` 的独立模板战力，不并入角色属性面板极限 |

后续可以在同一页面增加“账号综合战力/队伍战力”模式，但不能复用角色属性面板结论冒充综合战力。

## 运行时合并顺序

计算核心必须保留运行时的合并顺序和取整点。顺序不只是展示顺序，还会影响中间取整后的结果。

```text
calAttribute_lv
round
calAttribute_xf
round
calAttribute_equipment
round
calAttribute_suit
round
calAttribute_fashion
round
calAttribute_neidan(current page)
round
calAttribute_neidan(titles, floor)
round
calAttribute_neidan(each magic, floor)
round
add all wings
round
add all feathers
add xianpo
add matrix
add starcore
add meridians
add smelt
add breathing
round
```

实现时不要把所有模块属性先相加再统一取整。模块级页面可以展示未合并前的模块贡献，但总属性还原必须按上述顺序执行。

## 战力与属性字段

### 参与战力字段

`powerAttribute[1]` 当前有权重的字段：

| 属性 | 权重 |
|---|---:|
| 生命 `hp` | 1 |
| 魔法 `mp` | 2 |
| 攻击 `atk` | 10 |
| 防御 `def` | 30 |
| 命中 `hitVal` | 5 |
| 闪避 `dodge` | 5 |
| 暴击 `crit` | 5 |
| 韧性 `tenacity` | 5 |
| 幸运 `lucky` | 5 |
| 守护 `guardian` | 5 |
| 穿透 `break` | 10 |
| 减伤 `protect` | 10 |
| 回血 `healHp` | 18 |
| 回魔 `healMp` | 36 |

### 非战力字段

`defP`、`defSubtractP`、`hitValP`、`dodgeP`、`critP`、`tenacityP`、`luckyP`、`guardianP` 当前权重为 0。它们可以作为机制展示字段保留，但不能计入 `fightPower`。

元素抗性来自角色怪物模板 `monster.resist`，进入属性展示，但当前未进入 `powerAttribute[1]` 战力权重。

## 数据加载策略

### 离线产物

第一阶段继续输出静态 JSON：

```text
output/role_extreme_stats_source_map.json
output/role_extreme_stats_modules.json
output/role_extreme_stats_curves.json
output/role_extreme_stats_warnings.json
```

同步到前端静态数据后由现有 `/api/data/<name>` 或 `frontend/public/data/<name>.json` 读取。

### 打包 dataApi 的计算模式

极限属性是重计算模块，可以直接打包所需 `dataApi`。推荐做“模块级 lazy data pack”，不要把整个 `dataApi` 一次塞进首屏：

```text
frontend/public/data/extreme-stats/
  manifest.json
  core-data.json
  equipment-data.json
  fashion-data.json
  cultivate-data.json
  magic-wing-data.json
  matrix-starcore-data.json
```

`manifest.json` 记录每包的表名、hash、行数和生成时间。计算 worker 根据玩家当前打开的模块按需加载对应 data pack。

## 通用数据结构

### 属性向量

```ts
type AttrVector = Partial<Record<
  'hp' | 'mp' | 'atk' | 'def' |
  'healHp' | 'healMp' |
  'hitVal' | 'dodge' | 'crit' | 'tenacity' | 'lucky' | 'guardian' |
  'break' | 'protect' |
  'lightResist' | 'darkResist' | 'waterResist' | 'fireResist' |
  'woodResist' | 'soilResist' | 'windResist' | 'rayResist' |
  string,
  number
>>;
```

规则：

- 不存在的字段只表示未贡献，不能在公式里静默当作真实 0 来源。
- 合并时可以把缺失字段按 0 参与加法，但输出必须保留贡献来源。
- 所有参与战力的值必须是有限数字，否则该模块 fail。

### 阶段点

```ts
interface StagePoint {
  moduleKey: string;
  stageKey: string;
  label: string;
  unlock?: {
    roleLevel?: number;
    worldLevel?: number;
    conditions?: string[];
  };
  params: Record<string, unknown>;
  attrs: AttrVector;
  fightPower: number;
  evidence: EvidenceRef[];
  warnings: WarningItem[];
}
```

`stageKey` 必须由真实阶段参数生成，例如：

```text
wing:101:lv=30
heart:atk=240
magic:1001:lv=10:growth=75:blessing=1,3,4,5:soulLv=10
starcore:101:q=6:satellite=20:world=230
```

禁止使用 `max`、`default`、`auto` 这类无法追溯的阶段 key 作为最终结果。

### 模块计算器接口

```ts
interface ExtremeModuleCalculator {
  key: string;
  label: string;
  status(context: ExtremeContext): ModuleStatus;
  enumerateStages(context: ExtremeContext, scope: StageScope): Iterable<StageCandidate>;
  calculate(context: ExtremeContext, candidate: StageCandidate): StagePoint;
}
```

`status` 只允许返回：

```text
ready
partial
blocked_missing_table
blocked_missing_runtime
blocked_unknown_generation
blocked_invalid_data
```

任何 `blocked_*` 都不能输出伪极限值，只能输出 warnings 和可验证的 source map。

## 计算模式

### 角色总属性还原

输入：

```ts
interface CharacterTotalRequest {
  heroId: number;
  roleLevel: number;
  worldLevel: number;
  moduleStages: Record<string, StageCandidate | StageCandidate[]>;
}
```

输出：

```ts
interface CharacterTotalResult {
  heroId: number;
  roleLevel: number;
  worldLevel: number;
  attrs: AttrVector;
  fightPower: number;
  moduleContributions: StagePoint[];
  roundingTrace: Array<{ step: string; attrs: AttrVector }>;
  warnings: WarningItem[];
}
```

只要存在 `requiredForCompleteCharacterTotal=true` 的模块缺数据，例如当前吐纳缺表，`complete=false`，并明确标记缺口。

### 模块阶段曲线

输入：

```ts
interface ModuleCurveRequest {
  moduleKey: string;
  heroId?: number;
  roleLevel?: number;
  worldLevel?: number;
  target?: 'fightPower' | keyof AttrVector;
  range?: Record<string, number | number[]>;
}
```

输出每个阶段点的属性和战力。玩家查看任意阶段时，只读取对应 `stageKey`，不需要重新生成全部总属性。

### 极限方案

输入：

```ts
interface ExtremePlanRequest {
  target: 'fightPower' | keyof AttrVector;
  modules: string[];
  constraints: {
    heroId: number;
    roleLevelMax?: number;
    worldLevelMax?: number;
    includeUnavailableTitles?: boolean;
    includeClosedRows?: false;
  };
}
```

输出：

```ts
interface ExtremePlanResult {
  target: string;
  score: number;
  attrs: AttrVector;
  fightPower: number;
  selectedStages: StagePoint[];
  excludedCandidates: Array<{ moduleKey: string; reason: string }>;
  warnings: WarningItem[];
}
```

`target='fightPower'` 使用 `powerAttribute[1]` 加权。`target='atk'` 等单项属性只按该属性最大化，不和战力最大方案混用。

## 各模块详细设计

### 角色等级基础

来源：

```text
monster.*.json
exp.*.json
```

阶段参数：

```text
heroId
roleLevel
```

公式：

```text
attr[field] = monster[heroId][field] * exp[level][field]
```

字段：

```text
atk, def, hp, healHp, healMp, mp, hitVal, dodge, crit, tenacity, lucky, guardian, break, protect
```

抗性：

```text
monster.resist -> getResistObjById -> lightResist/darkResist/...
```

阶段枚举：

- `roleLevel` 来自 `exp.level`。
- `heroId` 来自 `role.id` 或角色 `monster.id`，二者必须能对上。

### 修炼/心法

来源：

```text
heart.*.json
```

阶段参数：

```text
fixHeartList: { hp, mp, atk, def, healHp, healMp }
```

公式：

```text
attr[prop] += heart[level][prop]
```

阶段枚举：

- 每个属性独立等级。
- 等级上限来自 `heart.level` 最大值。
- 角色等级限制来自 `heart.limit`，不能忽略。

极限策略：

- 无资源约束时，每个属性取允许范围内最大等级。
- 有目标属性时，只提升目标相关属性。
- 有资源约束时，需要背包/成本模型，第一版不做假设。

### 装备基础、词条、强化、宝石、套装

来源：

```text
equip.*.json
equipUpgrade.*.json
equipUpgradeValue.*.json
stone.*.json
equipSuitAttribute.*.json
equipAffix.*.json
```

运行时输入形态：

```text
hero.equipments[part].data.attr
hero.equipments[part].data.affixAttr
hero.equipments[part].lv
hero.equipments[part].stone
```

阶段参数：

```text
part
equipId
upgradeLevel
stoneIds[]
affixAttr
```

计算拆分：

1. 基础属性：`data.attr`。
2. 词条属性：`data.affixAttr`。
3. 强化属性：`calEquipUpgradeValue(data, lv)`。
4. 宝石属性：按孔位和 `stone.attribute/attributeValue` 累加。
5. 套装属性：按已穿装备的 `suitAttribute` 与角色序号取套装 id，再按件数取最高满足档。

极限策略：

- 装备选择是组合问题，不能简单逐件取最高战力，因为套装属性跨部位。
- 第一版使用 slot dynamic programming：
  - 每个部位枚举候选装备、强化等级、宝石组合。
  - 状态保留 `partIndex + suitCounts + targetScore`。
  - 最终再按套装档位补属性。
- 词条极限必须先确认 `equipAffix` 和装备洗练运行时。未确认前只支持“给定词条属性计算”，不输出词条极限。
- 宝石极限可按孔位数量和宝石 group 枚举，但必须遵守装备孔位、宝石 group 和最高等级。

固定战力修正：

```text
fixPower = round(max(equipmentPowerWithoutJewelry - role.equipMinus, 0)
  / max(role.equipSum - role.equipMinus, 1)
  * role.firePoint)
```

这是属性面板修正值，不是属性加权的一部分。页面需要单独展示。

### 时装与时装宝珠

来源：

```text
equipFashion.*.json
equipFashionBall.*.json
```

运行时：

```text
calAttribute_fashion(fashions, fashionInfo)
```

公式：

```text
base[attr] = sum(equipFashion.attributeValue)
ballBonus[attr] = sum(equipFashionBall[0..fashionInfo.id].attributeValue[attr])
attr += base[attr] * (1 + ballBonus[attr])
```

阶段参数：

```text
fashionIds[]
fashionBallLevel
```

极限策略：

- 给定时装集合时严格计算。
- 配置极限可以枚举所有未关闭 `equipFashion`，但必须标记可获得性未知。
- 宝珠等级必须从 `equipFashionBall.id/rank/level` 推导，不能直接假设连续等级有效。

### 内丹、丹气、丹元

来源：

```text
danqi.*.json
danyuan.*.json
beskill.*.json
buff.*.json
```

运行时：

```text
getAttriByNeiDan_attr(page)
calAttribute_neidan(attrs, pageAttrs)
```

运行时只读取存档页中已经生成好的 `danqi.attr`，不直接从 `danqi` 表推导最终属性。

阶段参数：

```text
pageIndex
danqiSlots[]
danyuanSlots[]
attr
```

第一版策略：

- `restoreCharacterTotal` 支持给定存档态 `danqi.attr` 的严格计算。
- `moduleCurve` 支持 `danqi` 表中明确的等级、类型、属性范围展示。
- `extremePlan` 暂时 blocked，直到追清丹气生成、精炼、丹元融合、品质升级对最终 `attr` 的影响。

已有丹元机制说明可复用 `role_danyuan_effect`，但它解释战斗效果，不等价于丹气属性极限。

### 称号

来源：

```text
title.*.json
titleAttribute.*.json
```

运行时：

```text
titles.list -> getAttriByTitles(titleIds, roleLevel)
title.buteId -> titleAttribute by level
```

取档规则：

```text
按 buteId 找 titleAttribute，返回第一条 level >= roleLevel 的属性档
```

阶段参数：

```text
titleIds[]
roleLevel
```

极限策略：

- 给定称号集合时严格计算。
- 配置极限可以输出“全配置称号极限”，但必须把活动、限时、VIP、条件获取型称号标为 eligibility unknown。
- 不得把所有 `title` 默认当成玩家可同时拥有的真实上限，除非可获得性链路被证明。

### 法宝与器魂

来源：

```text
magicWeapon.*.json
magicWeaponSoul.*.json
magicWeaponSoulLv.*.json
```

运行时：

```text
getAttriByMaigc(magic)
calMagicWeaponSoul(soulData)
```

法宝属性公式：

```text
hp     = floor(0.5 + base.hp     + growth * (1 + 0.5 * hasBless4) * hpAdd     * lv)
mp     = floor(0.5 + base.mp     + growth * (1 + 0.5 * hasBless3) * mpAdd     * lv)
atk    = floor(0.5 + base.atk    + growth * (1 + 0.5 * hasBless1) * atkAdd    * lv)
def    = floor(0.5 + base.def    + growth * (1 + 0.5 * hasBless5) * defAdd    * lv)
healHp = floor(0.5 + base.healHp + growth * healHpAdd * lv)
healMp = floor(0.5 + base.healMp + growth * healMpAdd * lv)
```

器魂常驻属性：

```text
attr[attrName] += magicWeaponSoul.attributeValue[i] * soulData.lv
```

阶段参数：

```text
magicWeaponId
lv
growth
blessing[]
soulData.lv
soulData.spell[]
```

极限策略：

- `growth` 候选范围来自 `magicWeapon.growth`，不能假设小数精度。
- 祝福组合来自 `magicWeapon.blessing`，不同目标属性选择不同祝福。
- 器魂候选来自 `magicWeaponSoul` 与 `magicWeaponSoulLv`，要按 group、quality、level 分层。
- 主动技能效果不进入角色属性战力，保留为说明扩展，不参与属性极限。

### 翅膀

来源：

```text
wing.*.json
wingAttribute.*.json
```

运行时：

```text
getWingAttr({ id, lv })
getUserAllWingsAttrsAndPower(wingBag.items)
```

公式：

```text
wing.buteId + wingLevel -> wingAttribute.attribute/attributeValue
```

阶段参数：

```text
wingId
wingLevel
```

极限策略：

- 运行时会汇总 `wingBag.items` 中所有翅膀属性。
- 角色必须在出战位配置了 `wingId > 0` 才会读取羽毛，翅膀属性本身来自 `wingBag.items`。
- 阶段曲线按每个翅膀独立输出，并提供“所有翅膀同阶段汇总”。

### 羽毛

来源：

```text
feather.*.json
featherAttribute.*.json
```

运行时：

```text

```

## 优化策略

### 可加性模块

以下模块在没有资源约束时可直接枚举每个阶段点并按目标取最大：

```text
role_base
heart
fashion
title_given_set
magic_given_weapon
wing
xianpo
starcore
meridians_base
smelt_given_quality_type
```

### 组合模块

这些模块必须使用组合优化或明确标记为 partial：

| 模块 | 原因 | 策略 |
|---|---|---|
| 装备 | 部位、套装、孔位、词条互相影响 | slot DP + suit state |
| 法宝祝福 | 祝福对不同属性放大不同 | 枚举 blessing 组合 |
| 羽毛 | 多属性随机与品质范围 | 生成链确认后枚举/优化 |
| 阵法核心 | 阵核属性与套装最低品质绑定 | core generator + suit state |
| 经脉丹药 | 丹药百分比放大基础值 | 确认丹药生成后枚举 |
| 熔炼品质槽 | 每级品质槽影响多属性 | 枚举 qualityType[] |

### 评分函数

```ts
function score(attrs: AttrVector, target: Target, weights: PowerWeights): number {
  if (target === 'fightPower') return floor(weightedSum(attrs, weights));
  return attrs[target] ?? 0;
}
```

战力目标和单属性目标必须分开输出。不能用战力最高方案解释为攻击最高、生命最高或实战最优。

## Warning 与失败规则

硬失败：

- 缺 `powerAttribute` 或缺 `powerAttribute[1]`。
- 运行时入口缺失且该入口是公式来源。
- 必需表缺失，例如吐纳表。
- 参与战力的属性值不是有限数字。
- 需要战斗配置才能确认次数/帧数，但配置缺失。

可继续但标记 partial：

- 可获得性未知的称号、时装、活动道具。
- 给定存档态可算，但生成极限未追清的丹气、羽毛、阵核、经脉丹药。
- 独立战斗技能效果可解释，但未进入角色属性面板的神器/神魔。

禁止行为：

- 不用 `0`、空数组、最大行、第一行冒充缺失配置。
- 不手写战力权重。
- 不按中文名推断公式。
- 不把攻略帖人工极限数值当作当前版本真值。

## 前端展示设计

前端是独立入口，不和现有角色页导航结构强耦合。

建议路由：

```text
/extreme-stats
```

页面结构：

1. 顶部模式切换：角色总属性、模块阶段、极限方案。
2. 左侧模块列表：按运行时顺序展示模块状态。
3. 主区域：
   - 阶段选择器
   - 属性贡献表
   - 战力贡献
   - warning/缺口
4. 右侧方案摘要：
   - 当前目标
   - 当前阶段 key
   - 当前模块贡献
   - 总战力或单属性最大值

显示规则：

- 玩家默认看到中文属性、阶段、战力，不看到内部字段名。
- 高级审计模式才显示 evidence。
- blocked 模块展示明确原因，不展示伪数值。
- 常量写在说明区，真正随阶段变化的值放进表格。
