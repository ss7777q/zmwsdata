# 极限属性模块探索

## 直接结论

这是一个全新的数据分析功能，第一阶段不应从现有前端页面拆组件。正确主线是复刻游戏运行时的角色属性汇总链路，再在此基础上做“极限战力方案”和“单项极限属性方案”。

当前权威入口是 `D:\zmws\GameAnalysis\data\index.js` 的 `UserInfoManager.getUserInfo -> UserInfoManager.calUserInfo -> UserInfoManager.calFightPower`。`ModelManager.calFightPower` 与 `UserInfoManager.calFightPower` 都按 `powerAttribute` 表 id=1 加权求和后向下取整，不能硬编码权重。

## 战力换算口径

战力公式：

```text
fightPower = floor(sum(attr[field] * powerAttribute[1][field]))
```

当前 `dataApi/powerAttribute.2ddff.json` 的 id=1 权重：

| 属性          | 权重  |
| ----------- | ---:|
| 生命 hp       | 1   |
| 魔法 mp       | 2   |
| 攻击 atk      | 10  |
| 防御 def      | 30  |
| 命中 hitVal   | 5   |
| 闪避 dodge    | 5   |
| 暴击 crit     | 5   |
| 韧性 tenacity | 5   |
| 幸运 lucky    | 5   |
| 守护 guardian | 5   |
| 穿透 break    | 10  |
| 减伤 protect  | 10  |
| 回血 healHp   | 18  |
| 回魔 healMp   | 36  |

`powerAttribute` id=2 与 id=3 的用途需要继续沿运行时确认。当前角色总战力、阵法、经脉、翅膀、羽毛、称号等已查到的路径都使用 id=1，不能猜测 id=2 或 id=3 的业务含义。

攻略帖《极限战力与极限属性》只作为辅助玩家口径：它把攻击、生命、防御、魔法、回血、回魔称为主六维，把命中、闪避、暴击、韧性、幸运、守护称为副六维，并明确说明“极限战力”不代表实战最优属性。

## 运行时属性汇总链路

`UserInfoManager.getUserInfo(record, heroId)` 先从存档里取角色、全局系统和出战位数据，再调用 `calUserInfo` 合并属性。

| ---:| ------------- | ---------------------------------------------------- | ------------------------------------------------- | ------- | -------------------------------------------- |
| 1   | 角色等级基础        | `calAttribute_lv`                                    | `monster`、`exp`                                   | 是       | 按角色怪物模板属性乘等级成长表，另加元素抗性                       |

## 固定战力修正

属性面板还存在 `UserInfoManager.calFightPower_fixPoint(heroId, equipments)`：

```text
fixPower = round(max(equipmentPowerWithoutJewelry - role.equipMinus, 0) / max(role.equipSum - role.equipMinus, 1) * role.firePoint)
```

这个修正只用装备属性计算，并跳过首饰部位。它不是普通属性加权的一部分，但如果后续页面要复刻属性面板展示，需要单独输出。

##





| 缺口                                                                | 影响            | 处理方式                  |
| ----------------------------------------------------------------- | ------------- | --------------------- |
| `breathing`、`breathingAcupoint` 表在当前 `deployable-app/dataApi` 未找到 | 不能完整复刻角色总属性   | 数据同步前必须输出 warning 或失败 |
| `powerAttribute` id=2/id=3 用途未确认                                  | 不能暴露可选权重口径    | 第一版只使用运行时确认的 id=1     |
| 丹气、丹元、羽毛等运行时读取的是存档内最终 `attr`                                      | 不能只靠总表推导最终可选池 | 后续需要沿生成/洗练逻辑追配置表      |
| 法宝祝福、器魂、熔炼、经脉丹药存在倍率或品质槽                                           | 不能把当前结果拍成静态属性 | 输出必须保留来源层和公式层         |
| 攻略帖含大量人工极限结果                                                      | 不能直接当作当前版本真值  | 只能作为核对和玩家术语来源         |

## 后续实现边界

建议新增独立 extractor，而不是改现有前端页面：

```text
scripts/extract/role_extreme_stats.js
```

第一版 extractor 的职责：

1. 读取 `dataApi` 表和必要的游戏运行时证据。
2. 复刻 `UserInfoManager.calFightPower` 的 id=1 权重加权。
3. 输出模块级 source map、属性贡献、战力贡献和 warnings。
4. 对缺失关键表直接 warning 或失败，不填 0、不 mock、不猜上限。
5. 同时支持 `maxFightPower` 与 `singleAttribute` 两种目标，不把二者混用。

前端只应作为后续承载层。等数据模型稳定后，再决定展示为表格、对比器或方案生成器。
